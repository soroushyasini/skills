# قالب‌ها و شیوه‌های خروجی صورت‌جلسه

هنگام تولید صورت‌جلسه، قالب مناسب درخواست را از این مرجع انتخاب کن.

# ساختار استاندارد خروجی

خروجی پیش‌فرض باید از ساختار زیر پیروی کند.

## ۱. عنوان

عنوان باید مشخص و توصیفی باشد.

فرمت پیشنهادی:

```markdown
# صورت‌جلسه بررسی [موضوع جلسه]
```

نمونه:

```markdown
# صورت‌جلسه بررسی الزامات توسعه سامانه مناقصات و مزایدات
```

---

## ۲. مشخصات جلسه

در صورت موجود بودن اطلاعات، این موارد را درج کن:

```markdown
**موضوع جلسه:** ...
**حاضرین:** ...
**تاریخ جلسه:** ...
**محل برگزاری:** ...
```

اگر برخی اطلاعات وجود ندارد، از جای‌خالی استفاده کن.

نام افراد را فقط در صورتی درج کن که در ورودی آمده باشند.

---

## ۳. مقدمه کوتاه

پس از مشخصات جلسه، یک پاراگراف کوتاه بنویس که توضیح دهد جلسه درباره چه موضوعی
بوده است.

نمونه ساختار:

```markdown
در این جلسه، وضعیت فعلی سامانه ... بررسی شد و نیازمندی‌های جدید مورد نظر برای
بهبود ... مطرح شد. پس از بررسی موارد، مقرر شد تغییرات و قابلیت‌های زیر در برنامه
توسعه سامانه قرار گیرد.
```

مقدمه معمولاً بین ۲ تا ۴ جمله باشد.

از نوشتن مقدمه‌های کلی و تزئینی خودداری کن.

---

# ۴. مصوبات و اقدامات

اگر جلسه شامل چند اقدام یا الزام مشخص است، آن‌ها را در جدول قرار بده.

ساختار پیش‌فرض:

```markdown
## مصوبات و اقدامات مورد توافق

| ردیف | موضوع | شرح اقدام |
|---:|---|---|
| ۱ | ... | ... |
| ۲ | ... | ... |
```

### ستون «موضوع»

یک عنوان کوتاه و شفاف برای هر مورد ایجاد کن.

مثلاً ورودی:

```text
دلار به واحد اضافه شود
```

به:

```text
واحد پول دلار
```

تبدیل شود.

### ستون «شرح اقدام»

توضیح کامل‌تر و رسمی مصوبه نوشته شود.

مثلاً:

ورودی:

```text
اپلود چند فایل اضافه شود
```

خروجی:

```text
امکان بارگذاری هم‌زمان چند فایل برای هر رکورد به قابلیت‌های سامانه اضافه شود.
```

# خروجی پیش‌فرض

اگر کاربر فرمت خاصی درخواست نکرده است، خروجی را در **Markdown** تولید کن.

ساختار معمول:

```markdown
# عنوان صورت‌جلسه

**موضوع جلسه:** ...
**حاضرین:** ...
**تاریخ جلسه:** ...
**محل برگزاری:** ...

پاراگراف مقدمه

## مصوبات و اقدامات مورد توافق

| ردیف | موضوع | شرح اقدام |
|---:|---|---|
| ... | ... | ... |

## بخش تخصصی در صورت نیاز

...

## جمع‌بندی

...

**امضا و تأیید حاضرین**

نام و امضا: ...
```

---

# خروجی Word یا PDF

اگر کاربر درخواست Word یا PDF کرد:

- همان ساختار محتوایی حفظ شود؛
- سند کاملاً RTL باشد؛
- جدول‌ها RTL باشند؛
- عنوان‌ها از متن بدنه متمایز باشند؛
- فونت فارسی مناسب استفاده شود؛
- از شکستن جدول یا عنوان در انتهای صفحه جلوگیری شود؛
- متن نباید در تبدیل PDF به‌هم بریزد.

محتوای صورت‌جلسه نباید صرفاً برای زیباترشدن سند تغییر کند.

# حالت مختصر

اگر کاربر بگوید «صورت‌جلسه کوتاه»، ساختار زیر کافی است:

```markdown
# صورت‌جلسه ...

**موضوع:** ...
**حاضرین:** ...

## مصوبات

| ردیف | موضوع | اقدام |
|---:|---|---|
| ... | ... | ... |

## جمع‌بندی

...
```

---

# حالت رسمی‌تر

اگر کاربر بگوید سند برای مدیریت، مدیرعامل، هیئت‌مدیره یا بایگانی رسمی است:

- لحن را یک درجه رسمی‌تر کن؛
- جملات همچنان ساده و طبیعی بمانند؛
- از اصطلاحات محاوره‌ای استفاده نکن؛
- ساختار مشخصات جلسه، مصوبات، جمع‌بندی و امضا کامل باشد.

اما حتی در این حالت از زبان سنگین و مصنوعی اداری استفاده نکن.
